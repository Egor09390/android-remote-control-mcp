# zrok2 public tunnel on Android (experimental)

The Android APK contains a native arm64 `zrok2` client, built from pinned official
[openziti/zrok v2.0.9](https://github.com/openziti/zrok/releases/tag/v2.0.9)
source during GitHub Actions. It runs in the app process lifecycle as an external
native executable from Android's executable native library directory.

## Requirements

- Android arm64 phone, with access to the hosted zrok service.
- Free zrok2 account at [myzrok.io](https://myzrok.io), and the **zrok account
  enable token**, not a ngrok token.
- Accessibility permission for the app's MCP tools.
- **Keep MCP OAuth/bearer authentication enabled.** The public URL is not an
  authorization mechanism.

No VPS, publicly routable phone address, router port forwarding, or Termux is
required. Root is not required for the tunnel itself.

## On-phone setup

1. Open the app's **Server** tab, **zrok — no VPS** card.
2. Paste the zrok account token. The credential is saved only in Android app
   settings, and used to enroll the private zrok2 environment on first start.
   **Do not share the token in ChatGPT or commit it to Git.**
3. Optionally enter a public reserved name such as `s23-mcp` (lowercase
   letters, digits, hyphens). The app invokes `zrok2 create name -n public NAME`
   on startup, then `zrok2 share public --headless -n public:NAME ...`.
   The public namespace must support the chosen name and it must be available
   to your account. Leave blank for a randomly assigned, temporary URL.
4. Tap **Save zrok and start MCP**. The Android foreground MCP service owns the
   native zrok share process and stops it when MCP stops.
5. When the tunnel is actually connected, **ChatGPT connector** shows an
   HTTPS URL with `/mcp` and a copy button. No URL is advertised until zrok
   prints a public `*.share.zrok.io` endpoint.

Under the hood, zrok forwards HTTP requests to `127.0.0.1:<tunnelLocalPort>`
rather than to an exposed wireless-debugging or root ADB port.

## Important limitations

- zrok hosted service may show an **interstitial warning page** to public
  visitors. The provider documents `skip_zrok_interstitial` as a bypass
  header for noninteractive clients; ChatGPT's custom MCP connector may not
  send it. Thus a tunnel can be connected while ChatGPT MCP setup still fails.
  **An actual ChatGPT MCP end-to-end test is required.**
- Free hosted zrok has no uptime SLA. Published bandwidth limits and
  service policy can change.
- The APK has not been verified on a real Samsung Galaxy S23 / One UI 9 yet.
- The included server is the existing Android MCP server, **not** the full
  Python Google ARTEMIS agent runtime.
- In this build, only the official `*.share.zrok.io` HTTPS endpoint is parsed
  as connected. Custom-namespace endpoints need a further implementation.
- Android may kill an app's foreground service under battery restrictions.
  Exempt the app from battery optimization for more reliable operation.

## Implementation notes

- Native binary: `app/src/main/jniLibs/arm64-v8a/libzrok2.so` generated by
  `.github/workflows/own-vps-apk.yml` using Android NDK clang/Bionic.
- Private zrok environment: `<app filesDir>/zrok-home/.zrok2/`.
- Configuration: `ServerConfig.zrokEnableToken`, `zrokReservedName` and
  `TunnelProviderType.ZROK`.
- The zrok subprocess stdout is read for successful public URL discovery;
  its raw output is not logged because it can include sensitive data.
- The token from any other tunnel (ngrok, Cloudflare) is not compatible.
